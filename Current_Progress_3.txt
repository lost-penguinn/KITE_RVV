4. Important implementation details
Vector configuration
vsetvli supports:
- AVL-based vector length selection.
- Legal vtype validation.
- vill handling.
- Updates to vl, vtype, and destination GPR.
- Undo tracking for CSR and GPR changes.
Important configuration examples:
Immediate	Configuration	VLMAX
208	e32,m1	4
192	e8,m1	16

Vector instruction encoding
All .vv instructions share:
uint32_t generateVectorVVMachineCode(
    const ICUnit &block, uint32_t funct6, uint32_t funct3)


Operand mapping:
Assembly operand	Encoded field
First (vd)	vd
Second (vs2)	vs2
Third (vs1)	vs1

The encoder sets vm=1 for unmasked execution.

Current encoding table:
Instruction	funct6	funct3
vadd.vv	000000	000
vsub.vv	000010	000
vmul.vv	100101	010
vand.vv	001001	000
vor.vv	001010	000
vxor.vv	001011	000

Execution
All supported vector operations use:
void RVSSProcessor::ExecuteVector()


The function:
1. Decodes opcode, funct6, funct3, and register fields.
2. Identifies the vector operation.
3. Rejects unsupported masked instructions.
4. Checks vtype legality.
5. Checks LMUL=1.
6. Reads source vector elements.
7. Calculates each active lane.
8. Writes the resulting bytes into the destination vector register.
9. Records the old and new register values for undo/redo.
Arithmetic results are truncated to the configured SEW width.

For subtraction, the operation is:
lhs - rhs


where lhs = vs2[i] and rhs = vs1[i].

7. Current limitations
The following features remain unimplemented:
1. Vector loads and stores (vle*, vse*).
2. Masked vector execution.
3. LMUL values other than 1.
4. Full vstart behavior.
5. Named vtype syntax.
6. Additional arithmetic operations such as division, remainder, shifts, and saturating arithmetic.
7. Broader RVV 1.0 instruction coverage.
The simulator should therefore be described as having partial RVV support, not complete RVV 1.0 compliance.
