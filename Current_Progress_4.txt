1. Project Overview

Implementing partial RISC-V Vector Extension (RVV) support in the Kites RISC-V simulator.

The implementation covers:

Vector register storage and access.

Vector configuration through vsetvli.

Vector arithmetic and logical operations.

Vector memory loads and stores.

Vector register and memory undo/redo support.

Assembler parsing and machine-code generation for vector instructions.

The implementation is incremental. Each instruction is added through the existing assembler, processor, register, and UI architecture.

5. Vector Register Infrastructure

The register implementation includes:

ReadVreg(...)
WriteVreg(...)
ReadVectorElement(...)
WriteVectorElement(...)

Each vector register stores 16 raw bytes.

Vector memory and arithmetic operations use these interfaces rather than directly manipulating the register storage.

Vector register modifications are tracked in the processor's current_delta_ for undo/redo.

6. Assembler Infrastructure

A new syntax type was introduced:

O_VEC_C_LP_GPR_RP

It represents instructions of the form:

vle32.v v1, (a0)
vse32.v v1, (a0)

The parser:

parse_O_VEC_C_LP_GPR_RP()

extracts:

Destination/source vector register.

Base general-purpose register.

The parser stores the vector register in rd and the base GPR in rs1.

The syntax type is dispatched through parser.cpp, and the instructions are registered in instructions.cpp.

7. Vector Memory Machine-Code Generation

The following helper was added to code_generator.cpp:

uint32_t generateVectorMemoryMachineCode(
    const ICUnit &block,
    bool is_store
)
{
    const uint32_t vreg = VectorRegisterIndex(block.getRd());

    const uint32_t rs1 =
        static_cast<uint32_t>(
            std::stoi(block.getRs1().substr(1))
        );

    if (rs1 > 31)
        throw std::runtime_error(
            "Invalid vector memory base register"
        );

    const uint32_t opcode = is_store ? 0x27u : 0x07u;

    return (1u << 25)
         | (rs1 << 15)
         | (0b110u << 12)
         | (vreg << 7)
         | opcode;
}

The machine-code generator dispatches:

else if (block.getOpcode() == "vle32.v")
    code = generateVectorMemoryMachineCode(block, false);

else if (block.getOpcode() == "vse32.v")
    code = generateVectorMemoryMachineCode(block, true);

8. Vector Memory Execution

A new processor method was introduced:

void WriteVectorMemory();

It is declared in:

src/processor/rvss/rvss_processor.h

Its implementation is in:

src/processor/rvss/rvss_processor.cpp

The method:

Decodes the vector memory instruction.

Determines whether the instruction is a load or store.

Validates the supported addressing mode.

Checks vector configuration.

Reads vl and the base address.

Performs memory transfers.

Records changes for undo/redo.

Supported configuration checks

Currently requires:

SEW = 32

LMUL = 1

vstart = 0

vm = 1

Unit-stride addressing.

Single-field memory operation.

Load implementation

For each active element:

const uint32_t value =
    memory_controller_.readWord(base + i * 4);

The four bytes are copied into the appropriate vector-register element.

The original vector register is preserved for tail elements.

The resulting vector register change is recorded in:

current_delta_.register_changes

Store implementation

For each active element:

Reads four bytes from the source vector register.

Constructs a 32-bit value.

Writes the value to memory using writeWord.

Records old and new memory bytes.

Memory changes are recorded in:

current_delta_.memory_changes

WriteMemory dispatch

At the beginning of the existing WriteMemory() function:

uint8_t opcode = current_instruction_ & 0b1111111;

if (opcode == 0x07 || opcode == 0x27)
{
    WriteVectorMemory();
    return;
}

The existing scalar memory implementation remains unchanged.

11. Current Limitations

The current implementation does not yet support:

Vector memory operations for 8-bit and 16-bit elements.

Vector memory operations for 64-bit elements.

Strided vector memory operations.

Indexed vector memory operations.

Masked vector memory operations.

Segmented vector memory operations.

LMUL values other than 1.

Nonzero vstart execution and restart semantics.

Full RVV 1.0 behavior.

These limitations should be handled incrementally.
